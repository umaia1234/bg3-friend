# BG3 Friend 플레이 준비 절차

이 문서는 Windows에서 BG3를 플레이하며 Codex에게 시작·연결 준비를 맡기는 사용자를 위한 실행 지침입니다. 프로젝트 위치는 같은 스킬 폴더의 `project.local.json`을 사용합니다. 상세 도구 설치 방법은 **그 프로젝트**의 `docs/SETUP.ko.md`를 읽습니다.

## 미설정 항목 처리

먼저 현재 상태를 읽습니다. 이미 설치·승인·선택된 항목은 재설치하거나 같은 질문을 반복하지 않습니다. 점검 결과와 현재 대화를 대조하여 실제 누락 항목만 한 번에 정리합니다.

| 확인할 것 | 없거나 선택이 필요한 경우 |
|---|---|
| Windows Computer Use | 해당 작업에서 네이티브 창을 제어할 도구가 실제로 있는지 확인합니다. 없으면 연결·사용 가능한 Windows 작업으로 전환이 필요하다고 설명하고 먼저 물어봅니다. |
| BG3·Steam·프로젝트 경로 | 이미 설치된 게임과 이 저장소를 찾습니다. 다른 드라이브는 Steam `libraryfolders.vdf`와 `appmanifest_1086940.acf`로 확인합니다. 복수 설치나 다른 계정은 사용자 선택을 받습니다. 게임 구매·대용량 다운로드를 자동 시작하지 않습니다. |
| WSL 배포판·Python·Codex CLI | 설치된 배포판과 그 안의 도구를 점검합니다. 없으면 설치 대상과 필요한 재시작을 먼저 설명합니다. 승인 후 `docs/SETUP.ko.md` 2·4절을 따릅니다. 로그인은 현재 게임용 배포판에서 확인합니다. |
| Windows Python·Tk | 기존 실행기는 해당 게임 프로필 사용자의 `Python311/pythonw.exe`를 사용합니다. `start.ps1`은 해당 Python과 Tk를 확인합니다. 다른 위치를 쓰려면 현재 런처가 이를 지원하는지 먼저 확인합니다. 설정 파일 값만 바꾸고 다른 Python으로 실행된다고 가정하지 않습니다. |
| Script Extender·BG3Friend.pak·모드 등록 | 실제 설치 파일과 `Public/modsettings.lsx`의 BG3 Friend UUID를 확인합니다. 설치·재설치가 필요하면 영향받을 게임 파일, 백업 위치, 게임 종료 필요를 설명하고 승인받습니다. |
| LSLib·.NET·빌드 도구 | **모드 제작·설치가 필요할 때만** `docs/SETUP.ko.md` 3절의 `.tools`와 Windows .NET을 확인합니다. 이미 설치된 모드를 실행하기 위해 빌드 도구부터 재설치하지 않습니다. |
| Codex 로그인 | `doctor.py` 또는 그 배포판의 `codex login status`만으로 확인합니다. 로그인 필요 시 사용자에게 알려 브라우저 인증을 직접 마치게 합니다. 인증 창·암호·OTP를 대신 입력하거나 인증 파일을 읽지 않습니다. |
| 세이브·동료·전투 제어 | 현재 요청과 게임에 표시된 선택을 사용합니다. 정해지지 않은 선택만 물어봅니다. 앞으로의 기본값 저장은 사용자 요청이 있을 때 로컬 `preferences`에 기록합니다. |

질문은 실행할 변경이 보이게 구체적으로 합니다. 예: “Windows Python과 BG3 Friend 모드 등록이 빠져 있습니다. Python 설치 후 게임을 종료하고, 기존 파일을 백업한 뒤 모드를 등록해도 될까요?” 경로·세이브·동료는 실제 확인한 후보 이름을 제시합니다. 설치하지 않기로 한 항목을 임의로 대체하거나 계속 재시도하지 않습니다.

승인을 받으면 해당 항목을 완료하고 다시 점검합니다. 설치기·Steam·게임의 화면 조작은 Computer Use로 수행합니다. Python·WSL·패키징·파일 복사·진단 명령은 명령 실행 도구를 사용합니다. 실행 도구가 필요한 명령을 Windows Run이나 터미널 UI에 입력하는 우회 절차를 만들지 않습니다. UAC·인증·재시작처럼 사용자가 직접 해야 하는 단계가 나오면 정확히 그 단계만 넘기고, 완료된 뒤 기존 절차를 이어갑니다.

`modsettings.lsx`가 없는 최초 설치는 먼저 사용자 승인 범위에서 BG3를 주 메뉴까지 열어 프로필을 만든 뒤 정상 종료하고 설치합니다. 세이브 백업과 모드 설치는 게임이 닫힌 상태에서 합니다. 플레이 중인 게임에 저장하지 않은 진행이 있으면 종료 전에 사용자에게 확인합니다. 백업·설치·로그인 점검을 통과한 뒤 게임 시작으로 돌아옵니다.

## 화면에서 플레이 준비

### 1. 현재 화면과 프로세스 선택

사용 가능한 Computer Use 스킬을 읽어 초기화하고 반환된 앱·창에서 BG3 또는 LariLauncher를 고릅니다. 창을 전면에 둔 뒤 화면이나 접근성 트리를 읽습니다. 매번 관찰 → 한 동작 → 재관찰 순서를 따릅니다. 이전 실행의 좌표나 다른 창의 요소 번호를 재사용하지 않습니다.

이미 게임 세션과 친구가 연결되어 있으면 그 세션을 유지합니다. 명령 확인을 위해 게임을 껐다 켜거나 세이브를 다시 불러오지 않습니다. 시작 스크립트가 기존 프로세스를 재사용했더라도 실제 오버레이·현재 상태 확인은 수행합니다.

### 2. 런처와 주 메뉴

LariLauncher에서는 현재 DX11/Vulkan 선택을 유지하고 실제 **플레이** 버튼을 누릅니다. 표시된 안내는 내용을 먼저 읽습니다. 읽은 단순 안내 닫기와 설치·계정·파일 변경 동의는 구분하며, 알 수 없는 데이터 문제를 임의의 파일 삭제·검사 복구로 해결하지 않습니다. “다시 보지 않음” 같은 설정을 시작 편의상 바꾸지 않습니다.

게임 창을 다시 선택하여 로딩을 기다립니다. **진행하려면 아무 키나 누르십시오** 화면에서는 키를 보내고 화면이 바뀌었는지 확인합니다. 입력이 반영되지 않았으면 창 활성화·포커스를 다시 확인한 뒤 한 번 재시도합니다. 키 전송 성공만으로 주 메뉴에 도착했다고 말하지 않습니다.

### 3. 세이브 불러오기와 모드

- 사용자가 특정 세이브를 지정했다면 **게임 불러오기**에서 화면에 표시된 이름·캠페인으로 찾아 선택합니다.
- 사용자가 **이어하기**를 요청했다면 그 선택을 사용합니다. 이름 없는 “하자” 요청에서 여러 세이브 중 최신 파일을 임의로 고르지 않습니다.
- 선택이 없으면 보이는 세이브 후보를 확인하고 먼저 물어봅니다. 답을 받으면 Codex가 UI로 불러오기를 마칩니다. 사용자에게 전체 조작을 떠넘기지 않습니다.
- 모드 확인 창이 나오면 해당 세이브의 BG3 Friend 사용 여부를 읽습니다. 사용자에게 승인된 설정에 맞게 활성화하고 진행합니다. 모드가 누락되어 있으면 설치 절차로 돌아가 먼저 확인받습니다. 다른 모드를 임의로 비활성화하지 않습니다.
- 새 게임·저장·삭제·덮어쓰기는 시작 절차에 포함되지 않습니다. 별도의 사용자 요청이 있어야 합니다.

로드가 끝나면 `-Action Status`와 실제 게임 화면을 함께 확인합니다. 오래된 세션 파일은 성공 증거가 아닙니다. 신선한 snapshot이 없으면 게임이 아직 로딩 중인지, 모드가 활성화됐는지, Script Extender가 로드됐는지 확인합니다. 상태가 변하지 않으면 원인을 진단하며 같은 버튼을 반복하지 않습니다.

### 4. 친구 채팅과 동료 연결

게임 창이 전면에 있을 때 미니맵 아래 반투명 채팅을 찾습니다. 숨겨진 채팅은 별도 `pythonw.exe` 창이므로 필요하면 새 창 목록에서 **BG3 Friend** 창을 식별하고 그 창을 대상으로 조작합니다. 오버레이 좌표를 게임 창 좌표로 보내지 않습니다. 화면 밖으로 가려졌거나 게임이 최소화된 상태를 연결 실패와 구분합니다.

맡길 동료가 정해졌으면 **··· → 해당 동료** 또는 **함께하기**를 사용합니다. 설정되지 않았다면 실제 파티원 중 누구를 맡길지 먼저 물어봅니다. 사람 아바타나 다른 플레이어를 동료로 선택하지 않습니다. 초상화를 클릭하는 것과 친구 채팅의 동료 선택은 별개입니다.

첫 만남 카드는 실제 대화가 끝난 뒤 나타나며, 파티 합류 전에는 선택만 기억합니다. **합류 기다리는 중**은 정상적인 대기 상태입니다. 파티에 아직 없는 캐릭터를 연결 완료로 보고하거나 영입 대화를 임의로 진행하지 않습니다. 이미 **직접 할게**로 선택한 동료를 시작 확인 때문에 다시 연결하지 않습니다.

전투 제어 선택이 정해져 있으면 **전투도 맡기기** 체크 상태를 먼저 보고 일치할 때 그대로 둡니다. 첫 연결에서 선택이 없다면 한 번 물어봅니다. 전투는 게임 AI, 대화·탐험 판단은 Codex가 맡고 채팅과 파티·주변 정보가 Codex에 전달되어 사용량이 발생함을 설명합니다.

새로 불러온 세션에서 이번에 승인된 동료 연결은 UI로 시작합니다. 사용자가 명시적으로 쉬게 한 기존 세션은 재개 요청 없이 해제하지 않습니다. 로컬 `preferences`는 원하는 세이브·동료·전투 선택을 기록하는 자료이며 게임 자체의 저장된 선택을 덮어쓰는 명령이 아닙니다.

### 5. 입력 가능 여부와 완료 확인

사용자가 보낼 실제 문장을 지정했으면 채팅 입력란을 클릭하고 포커스를 확인한 뒤 그 문장만 입력·전송합니다. 단지 연결을 시험하려고 “안녕” 같은 문장을 만들어 보내지 않습니다. 사용자가 응답 시험을 원하면 시험 방법을 합의한 뒤 현재 세션의 실제 응답·오류를 확인합니다. 창을 띄우거나 호출 횟수가 늘어난 것만으로 응답 성공을 주장하지 않습니다.

일반적인 시작 완료는 **게임 세션 갱신 + 오버레이 표시 + 사용자 의도와 일치하는 동료 연결/대기 상태**입니다. 마지막에 현재 세이브·동료·준비 상태와 남은 사용자 조작이 있을 때 그 한 가지를 짧게 안내합니다. 실제 모델 답변을 확인하지 않았다면 그 검증을 했다고 말하지 않습니다.

빠진 선택을 묻거나 인증을 기다리는 동안은 완료가 아닙니다. 답이 오면 중단한 단계부터 이어갑니다. 영입 전 대기처럼 사용자가 선택한 정상 상태는 그대로 유지합니다. 준비 후의 기다림은 기존 runner가 맡으므로 Codex 예약 자동화나 반복 모델 호출을 만들지 않습니다.

## 종료·복구

잠시 멈춤은 **··· → 잠깐 쉬기**, 전체 친구 종료는 **··· → 대화 종료**입니다. 게임까지 닫아 달라는 요청이 없다면 게임은 유지합니다. 종료 후 runner·오버레이 상태를 확인합니다. 강제 프로세스 종료나 `runner.lock` 삭제는 정상 종료의 대체가 아닙니다.

부분 실행·오류는 현재 프로세스, 최근 heartbeat, 현재 세션의 오류를 함께 확인합니다. 로그에서 필요한 오류 구간만 읽고 인증 자료나 전체 대화를 출력하지 않습니다. 원인을 확인한 다음 사용자 요청 범위 안에서 복구하고, 새 설치·설정 변경이 필요해지면 변경 내용을 먼저 물어봅니다.
